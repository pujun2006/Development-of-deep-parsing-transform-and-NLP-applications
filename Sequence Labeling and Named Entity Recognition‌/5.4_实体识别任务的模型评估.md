在命名实体识别（NER，Named Entity Recognition）任务中，模型评估与传统的文本分类任务（如情感分析）有很大的不同。传统的分类任务只需统计每个样本或每个 Token 是否预测正确，而 NER 关注的是“实体块”（Chunk / Entity Span）的完整性和边界准确性。

以下从评估的核心指标、为什么不能只看 Token 级准确率、`seqeval` 工具的运行机制以及评估中的常见陷阱四个维度进行详细说明：

---

### 二、 为什么不能只看 Token 级准确率？

在代码第 6 部分中，我们特意排除了 `-100` 并使用 `seqeval` 来计算实体级指标，而不是直接用普通的 Token 级 Accuracy。原因在于“类别极度不平衡”**和**“边界严格性”：

1. **背景噪声（`O` 标签）占比极高**：
在任何文本中，绝大多数词汇都不是实体，而是普通的非实体词（标签为 `O`）。如果一个句子有 50 个词，其中只有一个实体 `[B-PER, I-PER]`（共 2 个词），其余 48 个词都是 `O`。
* 假设模型什么都不学，把所有词都预测为 `O`，其 Token 级准确率依然高达 $\frac{48}{50} = 96\%$。
* 但实际上，该模型对实体识别的能力为 **0**。Token 级准确率在这里会产生极大的欺骗性。


2. **边界与类别必须完全正确**：
假设真实实体是 `"New York"`（`B-LOC`, `I-LOC`）。
* 如果模型预测成了 `"New"`（`B-LOC`）和 `"York"`（`O`），或者把 `"New York"` 预测成了人名（`B-PER`, `I-PER`）。
* 在实体级别的评估中，这属于**完全预测错误**。而如果只看 Token 级，它可能有一半的 Token 猜对了，无法真实反映模型在真实业务场景（如信息抽取）中的表现。



---

### 三、 `seqeval` 的评估运作机制（结合代码逻辑）

在代码的 `compute_metrics` 函数中，数据转换的流程如下：

1. **过滤 `-100**`：
模型输出的 `predictions`（经过 `argmax` 转为数字 ID）和真实标签 `labels` 都包含了因 Tokenizer 切分产生的子词（Subword）以及特殊符号（如 `[CLS]`）。代码通过 `if l != -100` 过滤掉这些不参与计算的位置。
2. **还原为文本标签**：
利用 `label_list[l]` 将数字 ID 转换回 BIO 标签字符串（例如 `B-ORG`, `I-ORG`, `O`）。
3. **实体边界比对（Seqeval 核心）**：
`seqeval` 接收到形如 `['B-PER', 'I-PER', 'O', 'B-LOC']` 的标签列表后，会自动将它们还原成具体的**实体块结构**（例如：实体类型是 `PER`，起始位置在第 0 个词，结束于第 1 个词）。
* **判定正确的唯一标准**：预测的**实体类别**必须与真实一致，且**起止边界**必须完全吻合。哪怕多预测或少预测了一个字（边界错误），或者实体类型标错（如把组织机构错当成地名），整个实体块就被判定为预测错误。



---

### 四、 评估结果的解读与分类细分

`seqeval` 在计算出整体的 `overall_precision`、`overall_recall` 和 `overall_f1` 之外，如果需要，还可以打印出**每个具体实体类别**（如 `PER`, `ORG`, `LOC`, `MISC`）各自的指标。

在实际训练中，观察这些细分指标能够指导模型的调优方向：

* **某类实体 Recall 较低**：说明模型对这类实体的特征学习不够，漏报严重（可能是样本量太少）。
* **某类实体 Precision 较低**：说明模型容易“乱猜”，把很多非实体或其他类实体误判成了这一类（误报较多）。
