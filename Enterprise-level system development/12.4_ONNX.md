ONNX.py代码完整演示了将一个基于 **PyTorch** 的 Hugging Face BERT 文本分类模型**导出为 ONNX 格式**、**使用 ONNX Runtime (ORT) 进行高效推理**，并**验证前后精度一致性**的标准化生产级流程。

下面详细拆解代码的核心逻辑与工程要点：

---

### 一、 核心步骤逐行解析

#### Step 1: 加载预训练模型与分词器

```python
model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

device = torch.device("cpu")
model.to(device)
model.eval()

```

* **加载组件**：加载基础的 `bert-base-uncased` 分词器，并实例化一个用于二分类（`num_labels=2`）的文本分类模型。
* **推理模式（`model.eval()`）**：**至关重要的一步**。在导出模型前必须将模型设为评估模式，这会关闭 Dropout 和冻结 BatchNorm 等层的训练状态，确保导出后的静态计算图行为正确。

#### Step 2 & 3: 定义路径与准备虚拟输入 (Dummy Input)

```python
onnx_path = "bert_model.onnx"

dummy_input = tokenizer(
    "This is a sample input for ONNX conversion.",
    return_tensors="pt",
    padding="max_length",
    max_length=128,
    truncation=True
)

input_ids = dummy_input["input_ids"].to(device)
attention_mask = dummy_input["attention_mask"].to(device)

```

* **静态追踪**：PyTorch 在将模型转为 ONNX（一个静态或半静态的计算图）时，需要进行**追踪（Tracing）**。
* **Dummy Input**：代码传入了一句虚构的文本，通过分词器生成形状固定的 `input_ids` 和 `attention_mask`（长度为 128）。PyTorch 会拿着这个虚拟输入“跑一遍”前向传播，从而把整个模型的计算图结构和数据流向记录下来。

#### Step 4: 导出为 ONNX 模型

```python
torch.onnx.export(
    model,
    (input_ids, attention_mask),               # 传入位置参数元组
    onnx_path,
    input_names=["input_ids", "attention_mask"],
    output_names=["logits"],                    # 显式指定输出名称
    dynamic_axes={
        "input_ids": {0: "batch_size", 1: "sequence_length"},
        "attention_mask": {0: "batch_size", 1: "sequence_length"},
        "logits": {0: "batch_size"}
    },
    opset_version=14                           # 推荐升至 14 或以上，提高算子兼容性
)

```

这是整个转换的核心函数 `torch.onnx.export`：

* **输入输出命名**：`input_names` 和 `output_names` 显式定义了输入输出节点的名称，方便后续用 ONNX Runtime 调用时对号入座。
* **动态轴 (`dynamic_axes`)**：如果不设置，导出的 ONNX 模型将死死固定输入大小时为 128。通过设置 `dynamic_axes`，允许批次大小（`batch_size`）和文本序列长度（`sequence_length`）在推理时**动态变化**，适应不同长度的真实用户输入。
* **算子集版本 (`opset_version=14`)**：指定 ONNX 算子集版本为 14。版本越高，支持的 PyTorch 原生算子（如 LayerNorm、GELU 等）越完善，能有效避免转换时报错或算子不支持。

#### Step 5: 使用 ONNX Runtime 加载并推理

```python
session = InferenceSession(onnx_path)

onnx_inputs = {
    "input_ids": input_ids.cpu().numpy(),
    "attention_mask": attention_mask.cpu().numpy()
}

outputs = session.run(None, onnx_inputs)
logits = outputs[0]
predicted_class = np.argmax(logits, axis=1)

print("ONNX推理结果:", logits)
print("预测类别:", predicted_class)

```

* **脱离 PyTorch 依赖**：`InferenceSession` 使用纯 C++ 加载刚才生成的 `bert_model.onnx` 文件。此时模型已经不再依赖 PyTorch 框架。
* **NumPy 数据格式**：ONNX Runtime 的输入必须是 **NumPy 数组**（因此代码中调用了 `.cpu().numpy()` 将 PyTorch 张量转换）。
* **获取结果**：`session.run(None, ...)` 执行推理，返回输出列表，取第一个输出（`logits`）并通过 `np.argmax` 得到预测的类别标签。

#### Step 6: 精度对齐与校验 (Accuracy Assertion)

```python
with torch.no_grad():
    torch_outputs = model(input_ids=input_ids, attention_mask=attention_mask)
    torch_logits = torch_outputs.logits.cpu().numpy()

# 精度断言对比
np.testing.assert_allclose(torch_logits, logits, rtol=1e-3, atol=1e-5)
print("✅ PyTorch 与 ONNX 推理结果一致！")

```

* **为什么要对齐？**：模型在从 PyTorch 转换为 ONNX 图、以及在不同后端（如 TensorRT、ORT）计算时，可能会因为浮点数精度（FP32）细微的舍入误差导致结果偏移。
* **`np.testing.assert_allclose`**：这是一个极其实用的测试工具，用于对比 PyTorch 输出的 `torch_logits` 和 ONNX 输出的 `logits` 在相对误差（`rtol=1e-3`）和绝对误差（`atol=1e-5`）容忍范围内是否完全一致。如果超出误差范围，代码会直接抛出异常报错，确保转换后的模型在数学上与原模型等效。
