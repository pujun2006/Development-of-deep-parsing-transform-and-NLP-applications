TopK_TopP_TG.py代码实现并演示了大语言模型中非常经典的两种文本生成采样策略：**Top-K 采样**和 **Top-P（核）采样**。

下面详细拆解这段代码的原理与实现过程：

---

### 一、 准备工作：词表与概率分布

```python
import torch
import torch.nn.functional as F

# 模拟的中文词汇表及其对应的概率分布
vocab = ['我', '是', '学', '生', '在', '学', '习', '编', '程', '中', '信', '息', '技', '术', '方', '法']
logits = torch.tensor([1.2, 2.3, 1.5, 1.0, 2.5, 1.1, 2.0, 0.8, 1.9, 2.1, 0.9, 1.3, 1.7, 2.2, 1.4, 2.6])  # 模拟的模型输出原始得分
probabilities = F.softmax(logits, dim=-1)  # 转换为概率分布

```

* **`vocab`**: 包含 16 个中文单字的列表，模拟语言模型的词表。
* **`logits`**: 模型最后一层输出的未归一化原始得分（Logits）。
* **`F.softmax(..., dim=-1)`**: 将 Logits 转换为和为 1 的概率分布，让每个词都有被选中的概率（数值越大，概率越高）。

---

### 二、 Top-K 采样实现

Top-K 采样的核心思想是：**只保留概率最高的前 $K$ 个词**，将其他所有词的概率清零（或从候选池中剔除），然后对这 $K$ 个词重新归一化并进行随机抽样。

```python
def top_k_sampling(probabilities, k):
    # 1. 获取前 k 个最大的概率值及其在原概率张量中的索引
    values, indices = torch.topk(probabilities, k)  
    
    # 2. 从这 k 个概率值中按权重随机抽取一个（torch.multinomial 接受概率张量）
    chosen_index = torch.multinomial(values, 1)  
    
    # 3. 返回被选中词在原词表中的真实索引
    return indices[chosen_index.item()]

```

* **优点**：能够有效过滤掉长尾的低概率“错别字”或不合语法的词，保证生成质量。
* **缺点**：K 值是固定的。如果某个位置模型非常确定（概率高度集中），强制保留 K 个词可能会引入不必要的错误；如果上下文很模糊，K 太小又会限制模型的创造力。

---

### 三、 Top-P (Nucleus/核) 采样实现

Top-P 采样的核心思想是：**动态调整候选词池**。它将词按概率从大到小排序，然后从前往后累加概率，直到累加值达到预设阈值 $P$（例如 0.9 / 90%）为止。只有这个集合内的词才允许被采样。

```python
def top_p_sampling(probabilities, p=0.9):
    # 1. 将概率按降序排序，并保留排序后的索引
    sorted_probs, sorted_indices = torch.sort(probabilities, descending=True)  
    
    # 2. 计算累积概率（Cumulative Probability）
    cumulative_probs = torch.cumsum(sorted_probs, dim=-1)  

    # 3. 找到累积概率首次大于或等于 p 的截断位置索引
    idx = torch.where(cumulative_probs >= p)[0][0]

    # 4. 在截断后的子集（前 idx + 1 个词）中进行随机抽样
    chosen_index = torch.multinomial(sorted_probs[:idx + 1], 1)
    
    # 5. 返回被选中词在原词表中的真实索引
    return sorted_indices[chosen_index.item()]

```

* **优点**：具有自适应性。当模型确信下一个词是什么时（例如“人工智能”后面接“技术”概率很高），Top-P 自动缩小子集，候选词极少；当模型不确定时，候选池会自动放大，允许更多样化的词被选中。

---

### 四、 文本生成主循环

```python
def generate_text(probabilities, method='top_k', k=3, p=0.9, num_words=5):
    text = ''
    for _ in range(num_words):  # 循环生成指定数量（num_words）的词
        if method == 'top_k':
            word_idx = top_k_sampling(probabilities, k)
        elif method == 'top_p':
            word_idx = top_p_sampling(probabilities, p)

        text += vocab[word_idx.item()]  # 根据索引从词表中取出对应的字并拼接
    return text

```

* 这段代码模拟了自回归生成的过程。在真实的语言模型中，每生成一个词，模型的输入上下文就会更新一次、概率分布也会改变。
* **注意**：在这段演示代码中，每次采样使用的都是同一个静态的 `probabilities`（即输入分布没有随着生成过程动态改变），因此连续生成的 5 个字可能会重复。

---

### 五、 执行与输出

```python
# 执行Top-K采样（选择前3个词）
generated_text_k = generate_text(probabilities, method='top_k', k=3, num_words=5)
print(f"Top-K采样生成文本: {generated_text_k}")

# 执行Top-P采样（设置累积概率阈值为0.9）
generated_text_p = generate_text(probabilities, method='top_p', p=0.9, num_words=5)
print(f"Top-P采样生成文本: {generated_text_p}")

```

* 这两行代码分别调用了前文定义的生成函数，指定生成 5 个字符，并将结果打印输出。运行多次会发现由于 `torch.multinomial` 的随机性，每次生成的文本组合都会有所不同。

该代码输出出现奇奇怪怪结果的关键所在：

* 缺少自回归的动态更新（Stateless Generation）：
在真实的大语言模型（如 GPT-2）中，每生成一个新字，这个新字就会被追加到输入序列后面，模型会根据最新的上下文重新计算词表中所有词的新概率分布（即 logits 和 probabilities 每次都在变）。
但在该函数中，传入的 probabilities 是在循环外部定义好的死数据。无论循环多少次，每一轮抽样面对的都是完全相同的概率池。

* 为什么 Top-K 可能会一直重复？
由于概率是静态的，如果某一次随机抽样恰好抽中了原概率分布中最高的那个字（例如 logits 最高的 '在' 或 '是'），在下一次循环中它依然拥有最高概率。在没有惩罚机制的情况下，代码就会不断重复选中同一个字，导致死循环。

* 为什么 Top-P 结果可能毫无逻辑？
因为候选池虽然根据累积概率做成了动态截断，但被抽中的字与字之间没有任何语法或马尔可夫转移关系，完全是在一个固定的概率池里“盲抽”，拼出来的自然是一盘散沙。

* 总结建议：
这段代码仅适合用来单独测试和理解 Top-K 与 Top-P 算法在单个概率向量上的截断与抽样数学逻辑。但如果要实现真正的文本生成，必须把 probabilities 放入模型的前向传播（Forward Pass）循环中，让它随着生成内容的改变而动态刷新。
